# 差异填报与纠错 1.3.3

## 队员现在怎么填

1. 先搜索并选择已有对象。只读区展示已有资料，空白输入框不代表需要重填。
2. 展开需要修改的分组，只填一项也可以。例如只补入口朝向，不填名称、营业时间和层数。
3. 点选实际使用的来源说明，特殊情况再补文字；官网新信息写具体链接。观察时间预填当前时间，回填历史观察时必须修改。
4. 照片选填；保存草稿或提交审核后，在“我的提交”确认成功。

留空表示沿用正式记录，包括已收录的官网信息及原来源、原观察时间。原来未知仍未知；本轮不会自动联网补采官网，也不会把官网记录都当成当前营业事实。无变化不需要提交。

新增对象仅要求名称、窗口或商品的真实父级，以及本次来源和观察时间；其他字段可留空。总层数与坐标仍保持配套校验，不为省事接受无依据楼层或不完整坐标。

## 本次改进工作方式

- 用户实际反馈：重复填写默认信息耗时。今后先检查任务是否只需差异，不把数据模型所有字段都当成用户必填表单。
- 前端不把整条旧数据回填后重新提交；保留原始来源，避免被错误刷新成一次新的现场核验。
- 新增回归发现：发布增量原先浅覆盖 `field_evidence`，可能令未改字段的证据在合并结果中消失。改为按字段合并，不改库结构，不迁移历史数据；原始名录内仍存在的证据可正常保留。
- 切换对象先提醒清理未保存修改；草稿沿用提交时的基础版本，冲突交由人工核对。
- 旧教程保留为历史说明；当前页面的折叠分组和快捷来源以本次版本为准。

## 验证命令

运行 `node tests/test_contribution_form.cjs`、`python -m unittest discover -s tests -v`、`node verify_web_syntax.cjs`、`node --check information/app.js`、`python -m unittest test_campus_api.py test_poi_import.py`。
行为重点：只改位置描述保留官网营业时间和证据；单改商品价格无需重填名称和父级；相同值不造重复修改；0 元和 false 不丢失；旧草稿冲突不静默覆盖。

验证结果：48 项业务测试、9 项旧 API/导入测试通过，另有 7 项前端差异处理检查及语法检查通过。浏览器确认已有食堂名称无需填写、原营业时间显示为保留提示、所有修改分组默认折叠；本次未向正式名录提交测试记录。
