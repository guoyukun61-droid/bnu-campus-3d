# 团队填报完整重开流程

1. 先通知队友保存当前填报内容。尚未收到成功提示的文字先复制到备忘录。
2. 在普通 PowerShell 中运行项目根目录的 `reopen_team.ps1`。脚本自行读取项目路径，可从任意工作目录调用。
3. 脚本核对 8790、8792 的服务进程，以及本项目便携 cloudflared 的 8790 隧道。归属异常会报错，尚未停止任何进程；归属正确才关闭旧进程。
4. 建立新隧道后从本次日志读取地址，自动将它传入填报服务 `--origin`。无需手工复制链接修改另一条命令。
5. 出现绿色 `READY` 后，把 `Team URL` 发给队友。用户选择署名即可进入，修改项按需展开，空白保留正式资料。管理员使用 `http://127.0.0.1:8792/`。
6. 两个进程后台运行；启动完成后可以关闭当前 PowerShell 窗口。电脑保持联网、开机、不休眠。下次重开同样运行此脚本即可。

每次重新创建隧道通常得到不同域名。换域名后浏览器的 Cookie 不会自动转移；同名署名也不代表同一填写身份。旧提交保留在电脑中，找不到旧草稿时由管理员核对，不重复造店。

失败时复制 PowerShell 的完整错误给维护者，日志在私有 `data/life/contributions/`。没有绿色 READY 就不宣布网页可用。脚本不调整系统执行策略，若执行策略阻止脚本则保留错误信息并交由维护者判断。

## 本次改进工作方式

用户指出“关闭之前的重新打开即可”。正确地将旧隧道、精确地址校验和服务启动合并为一个完整操作，避免多次手动命令和固定 PID。区分脚本交付、进程启动、隧道注册与网页验证；只有验证通过才给出可用结论。
