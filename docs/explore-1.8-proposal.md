# 1.8 校园导览与卡通水彩：实施提案

原提案日期2026-10-02。更新2026-10-03：用户确认继续实施；阶段A已实现并验收，阶段B完成UI收敛及独立水彩样稿，尚未生成和应用经确认的水彩纹理。下文保留原提案决策依据，交付状态以 explore-1.8.0-acceptance.md 为准。

## 用户反馈及根因

1. 基础上色可以沿用，但道路不够清楚。已检查white_v6 GLB：道路网格 `Path_V3_Road_Network` 已存在，原材质 `V3_Road_Graphite` 为深灰；1.7上色逻辑将Road改为浅灰米色。初步判断有明显的道路/地面对比损失，遮挡及几何关系还需渲染检查，不声称道路数据丢失。
2. 首屏校园太小、缺少探索感。拟放大约15%–20%，自动缓慢旋转，用户拖动/缩放/选择对象/开始输入后停止；不在用户阅读时自行恢复。
3. 建筑点击落到第一家店铺，实体语义混淆。既有 `scene.js` 根据建筑ID找第一条POI并打开商户；应独立处理建筑档案和店铺列表。
4. UI模板感重。大幅口号、装饰英文、重复胶囊与独立卡片未形成校园导览系统；下一轮以实际任务和统一组件约束为准。

## 阶段A：先纠正交互，不等待复杂纹理

### 默认建筑模式

默认只显示必要楼名，不铺满店铺标记。点击科技楼→“科技楼”档案，显示已有可靠地址、用途及有来源的简介；简介不足只显示已知内容和“简介待补充”，不填模型想象的院系、年代与历史。

美食/饮品/购物等模式→显示相应商户；点科技楼→只列该类且已关联本楼的店铺，瑞幸显示二层。店名、楼名、窗口名保持独立ID，不修改原始POI类型凑效果。返回校园模式后关闭商户标签，恢复建筑选择。

模型不被复制；新增只读建筑API或现有接口的安全建筑投影，白名单仅包含ID、名称、可靠简介与来源摘要，不暴露原始技术审计。具体字段在实施时先写契约再改代码。

### 道路与镜头

保留白模原道路形状与深灰材质，检查是否共面闪烁、被地表遮挡或树木压住；只对确认的渲染问题处理。道路、建筑、树木以不同明度区分。

拟首屏距目标缩短约15%，缓慢自转一圈约3分钟，设暂停/继续按钮；页面后台和减少动态偏好不自转。拖动、缩放、选点或输入后保持停止，只有主动点击“继续漫游”恢复。放大以关键区域不被面板遮挡为验收，不硬套距离。

## 阶段B：独立样稿与风格统一

目标为一版“卡通水彩校园导览”，不是十站元素拼贴。道路和轮廓清晰，水彩只作用于表面层次，文字不做模糊纸纹。

- 选一套中文标题、一套正文，正文约14–16px；不堆装饰性英文、小字和口号。
- 只保留一套信息面板，普通列表用行分隔，不卡片套卡片。
- 导航与提示采用同一圆角、线宽、间距和图标系统；不混用Unicode装饰符充当成品图标。
- 纹理拟用浅灰石墙、砖红、低饱和绿、蓝灰窗面，水彩颗粒和边缘积色。屋顶参考影像，立面只能参考可对应的既有三维图或照片，未观察面注明示意。
- 先生成单张可判断风格的场景/UI样稿；确认后再生成可平铺屋顶/墙面/路面纹理。完整鸟瞰图不能直接当整栋建筑UV贴图。

## 计划验收与回退

- 默认点科技楼只出现建筑资料，饮品模式才出现瑞幸；无店建筑仍可选择；无名建筑不以商户命名。
- 不同楼层、同名分店、无建筑关联与校外店保留明确边界。
- 自转能停止、停止后不意外恢复；输入及读卡片时不转；缩放不使场景穿模，手机选中楼不被面板盖住。
- 道路连续、层次清楚、不改变模型几何；生成材质可切回基础上色，失败回退正常。
- 名称、菜单、来源与未知状态不因美术处理而丢失。进行现有全部测试和新增建筑/商户状态、相机状态测试，再做桌面与手机浏览器验收。
- 保留1.7、旧地图与原始影像；无新全局依赖、无密钥修改、无公开部署。

方案确认后先实施阶段A，再按选定样稿实施阶段B。产品版本仍为1.7.0；本提案不冒充已交付的1.8功能。
