# 校园UI审查：从资料面板到地图服务

2026-10-04。用户反馈：UI仍不理想，询问改进方式。本轮只检查并提出建议，未修改应用代码、数据或服务。

## 总体判断

主要问题是地图美术与UI没有形成统一体验、内容量与容器比例失衡、服务路径过长；不只是缺纸纹或银杏。上一轮统一颜色和字号、通过功能测试，不等于达到了用户期望的审美质量。

## 1. 窄屏建筑详情：可操作，但地图被遮挡

本轮打开当前页面，展开详情。品牌、提问、分类三条横栏叠加，下面又有大信息面板；地图可见面积很少。

![步骤1：当前窄屏建筑详情](D:/A-newdesktop/个人/本基/bnu_campus_blender_20260831/docs/ui-audit-20261004-01-narrow.png)

- 保留：分类与建筑资料能读取，正文可读。
- 高优先级：默认使用紧凑底部摘要卡，用户主动展开后才阅读长内容；地图常用操作不要被遮挡。
- 收拢品牌与次级入口，提问保持主入口。具体高度需用实际手机和侧边窗口测试，而不是以一个固定像素高度覆盖所有屏幕。
- 可访问性风险：移动地图的空间不足，底部细小文字叠在复杂场景上；本轮没有进行完整键盘/读屏测试。

## 2. 桌面建筑档案：结构清楚，但有明显文档感

1440×900下，科技楼只有简短资料，却使用整高侧栏；“建筑简介”主要是操作说明和待补提示。地图整体黄绿偏灰，屋顶很亮，UI同样使用淡底，缺少视觉层次。

![步骤2：桌面建筑档案](D:/A-newdesktop/个人/本基/bnu_campus_blender_20260831/docs/ui-audit-20261004-02-desktop.png)

- 保留：建筑和店铺分开，未知信息未被虚构。
- 高优先级：详情按内容定高度，长列表/对话才用长面板；简介未知时一行说明即可，不用大章节堆砌空信息。
- 美术方向：象牙白界面、墨绿交互、水彩仅作局部点缀；3D另外研究屋顶/墙体明暗、地表/道路区分和柔和阴影，不改变几何真实性。
- 信息入口：经典版、技术状态、上色开关可收入更多/设置，减少与核心提问、地图探索竞争。
- 字体：品牌或建筑大标题可少量宋体，交互和正文用清晰中等字重的黑体。字号一致还不够，还要有合适字重、行长、留白。

## 3. 楼内服务：可达，但路径长、内容弱

从科技楼详情点击“查看楼内服务”，再点“查看楼内吃喝”，得到只有一行瑞幸的整高面板。

![步骤3：楼内吃喝结果](D:/A-newdesktop/个人/本基/bnu_campus_blender_20260831/docs/ui-audit-20261004-03-services.png)

- 高优先级：建筑资料可提供带数量的“吃喝”分类入口，一次切换显示紧凑商户卡，仍遵守用户要求：未选择类别不显示具体店铺。
- 商户卡展示已知名称、二层位置、营业时间状态与两个操作：查看位置、询问助手；未知字段不造假。不为填满版面而放假菜单/图片。
- 图卡对应：选中店铺时地图给出同名短标签、楼层说明和温和高亮，不能只依赖颜色或一个小三角。

## 实施优先级（待用户确认，不自动实施）

1. 先用真实3D截图作底，设计首屏探索、建筑详情、店铺/助手结果三种关键状态；再做手机收起态。不要再生成虚构水彩校园作为整体效果承诺。
2. 先落实面板尺寸、信息密度、入口合并与少一次点击；最后统一字重/字号、边距、边框和选中反馈。
3. 3D美术独立试验：只做一个区域，比较光照、色板、柔和阴影和有限纸感纹理；不全校直接贴生成立面。
4. 最后放入银杏/纸纹和短过渡。静止状态不够清楚时，不用动效掩盖。

## 纠错：以后避免重复

- 不把功能回归全绿等同审美验收；同时检查内容密度与主要任务路径。
- 不用扩大容器、重复“待补”文案填充数据缺口。
- 样稿须以真实模型为底，避免概念插画与可交互3D之间落差成为UI误判。
- 先少量关键页面定稿，再编码，不一轮换一套全局CSS。
- 花纹服务于留白，不替代地图美术与信息设计。

## 限制

本轮采用product-design:audit技能，证据均为本轮实时浏览器截图。未对用户偏好做多人实验，建议属于基于界面的设计判断；没有进行完整无障碍认证、真实问答测试或位置准确性审查。当前没有看到新增背景纹饰，不能评估它们最终合成后的观感。未修改代码、停止服务或进行公开发布。
