## 主楼根因与保护验证

旧 `build_reference_v6.py` 使用 `[p for p in coords if p[1]>-253]` 截取后部。原始轮廓合法，但筛选后的首尾连线在本地米坐标约(176.4302,-251.3068)自相交，形成尖片和错误屋面三角化。不能靠改色或polygonOffset修复它。

`backend/main_geometry.py` 对分界线进行真正多边形裁剪：穿过边界的线段补交点，再保持环方向。Shapely独立计算的裁剪结果与本轮结果对称差面积小于1e-7平方米。此为数值一致性，不是地理精度。

`repair_white_v7_main.py` 保留后部22米表现高度、前部12个门廊/挑檐/台阶体块，重建依赖错误边的立面面片。Blender评估网格比对保护319个其他对象。

直接重新导出GLB时，部分未改对象发生导出层顶点排序差异；因此增加 `backend/glb_patch.py`，只把两个目标网格的属性/索引移入原GLB，其他二进制保持不动。独立读取最终GLB测试确认仅 `Building_267948584` 与 `Reference_Detail_267948584` 改变。旧GLB哈希保持 `cad45d69507d8594455a195ec8ad6815cf8321cc17ea394d64b96d95af795edb`。

## 接口与展示边界

`GET /api/app/buildings` 返回 `buildings:[{id,name,description,source,description_status}]`，以及`model`、`shop_mode`。白名单不带坐标、原始说明、推测层数、本地路径或提交审计。无依据的建筑历史与简介保持待补；已关联的店铺不作为楼名。

`scene.js` 使用 `visibleIds=null` 表示建筑模式，商户标记隐藏；显式ID集合才显示商户。建筑射线命中调用 `onBuilding`，不选名录第一家店。单栋楼内分类仍按真实关联筛选。

## 本次反馈总结：避免复发

- 建筑裁剪不得靠删除顶点；每次检查闭合环、自相交、三角化和局部多角度。
- 美术改色前建立道路/地表明度关系；不覆盖可读的道路原色后再用描边补救。
- 楼名、商户名、窗口名是不同实体；不要从首家POI推断建筑身份。
- 镜头与标记必须同时验收手机尺寸；世界空间尺寸不等于屏幕可读尺寸。
- 材质示意、工程合法性、真实精度三个概念分开。参考图未完成、模型未连通，必须明确披露。
