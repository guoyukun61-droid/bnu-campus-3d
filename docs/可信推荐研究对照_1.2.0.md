本轮是工程选型扫描，不是穷尽性系统综述，也没有完成新算法实验。下列来源来自方案阶段核对的论文页面、作者仓库和官方文档。本文不把论文作者自报效果迁移为本项目效果。

## 已落地的改进

1. 已审核的字段证据随价格与营业信息保留，并传到推荐卡片。
2. 新地点范围未知时不进入推荐；价格和耗时未知不假装满足硬约束。
3. 保持真实/模拟逐项标记。真实商品在演示模式中可能使用模拟排队，卡片必须明示。
4. 不动旧SQLite，不重写Three.js，增加小而独立的人工审核入口。

## 候选特色与待证明优势

候选定位是「面向课间生活的、证据可追溯的校园微尺度推荐」。校园—楼栋—楼层—窗口—商品的本地细节可能带来应用价值，但不是仅凭数据层级就能成立的算法创新。

两个候选研究问题：
- 在菜单和营业状态不完整时，证据时效与拒绝推荐策略是否减少错误建议？
- 在上课截止时间下，对步行/排队/出餐不确定性的处理，是否降低迟到而保持足够推荐覆盖？

## 后续实验设计（未执行）

- 基线A：现有确定性过滤与加权排序；B：加入证据有效性门槛；C：B加耗时区间约束。
- 固定同一测试场景与候选集，分别报告真实观察与模拟扰动。真实数据不足时不训练协同过滤或GNN。
- 记录预算违规率、时间违规/迟到率、返回候选覆盖、拒绝原因、来源完整度、响应耗时与自愿用户选择。
- 采用配对场景比较；阈值只在开发集调整，不用同一批评价场景反复调参后宣布优越。
- 先获得可复核的现场菜单和时间观测，再确定样本量与置信区间；十家试填只验证流程，不能证明算法显著优势。

下一阶段顺序：完成真实试填 → 修正表单和数据缺口 → 做基线实验 → 接自然语言解析。暂不做GraphRAG、多Agent编排或复杂训练模型。
