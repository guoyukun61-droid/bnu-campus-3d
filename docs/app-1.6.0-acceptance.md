## 使用入口

- 普通用户：[生活助手](http://127.0.0.1:8793/)。发现校园 → 分类 → 场所详情 → 地图查看。
- 本机管理员：[管理台](http://127.0.0.1:8792/)，使用既有本机 g 会话；[建筑与证据审查](http://127.0.0.1:8792/audit/)。无会话先回管理台登录。
- 建筑审查只读，不批准提交、不修改几何；普通用户服务没有审核接口或文件目录入口。
- 当前密钥仅由进程环境读取。退出服务或重启电脑后需重新临时提供；没有写入 .env、系统设置、代码或日志。

## 模型与失败恢复

保留当前官方 `deepseek-flash` 配置与独立适配器，接口核对依据：[DeepSeek 官方首次调用](https://api-docs.deepseek.com/)、[Chat Completions](https://api-docs.deepseek.com/api/create-chat-completion/)。未改用第三方中转。

错误事件包含 code、message、retryable、request_id，保留 text 兼容字段。区分未配置、鉴权、配额、繁忙、超时、取消与普通服务异常。

- 普通用户不直接看到鉴权排错细节，只知道助手暂不可用，以及地点浏览/条件筛选仍可用。
- 网络中断重试保留同一请求ID；仍在处理时提示等待，已经完成则返回缓存，不重复调用模型。
- 已确认失败后主动重试生成新ID；复用原来的回答位置，不重复插入用户问题或卡片。
- 停止按钮同时停止本机等待并请求后端终止后续步骤。已发送到上游的 HTTP 请求不保证立即中断，不能声称费用也被撤回。
- 已得到的卡片不会因后续错误清空。历史 `Failed to fetch` 在展示时转换成解释与恢复入口，不删除历史记录。
- 三维加载失败提供重载/返回地点入口；WebGL不可用提示继续使用文字服务。
- 本地服务完全断开时，只保证已加载资料可读；新的详情、筛选与助手回答须等待服务恢复。不能把“模型不可用”与“整个后端离线”混为一谈。

4. 新乐群北侧低楼 `900000000003`：独立体块已补建，但8m只是占位，名称、层数、用途仍未知。
5. 南苑57号楼：已有历史四层文献依据，尚不能可靠绑定到具体无名网格；28栋候选不能全部认定为校属。
6. 天猫校园超市：旧百度地址中的“4楼”仍需现场确认；已确认的全天营业不为地址背书。
7. 街电（巴依老爷新疆美食北师大店）：继续保留列表，错误落点已撤；新的准确位置待人工点选，不复制餐厅坐标。

## 本次纠错与防重复规则

1. 不让所有POI继承餐厅操作；类别决定能力，不以`menu=[]`存在就显示菜单。
2. 清理覆盖API、模型工具输出、历史卡片、地图选择和营业备注；不能只隐藏一处DOM文字。
3. 地址保留可独立识别的地点描述，管理性说明转入管理员审核，不丢弃证据、不补造地址。
4. “数据参数已改”不等于“GLB已改”，必须核对网格；“网格一致”也不等于“楼高真实”。
5. 实测发现酸梅汤被当成正餐，补充饮品过滤；缺口味标签不再通过重归一化得分获益。新增行为回归，而非只改文案。
6. 手机与桌面必须实际测量视口。测试时发现浏览器视口设置作用于当前选中标签，已在对应测试标签核对390像素而非仅相信设置调用成功。
