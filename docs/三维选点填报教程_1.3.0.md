# 三维选点填报 · 1.3.0

2026-09-24补充：1.3.2使用white_v6，增加小吃街近景、反向、俯视；选中楼体显示层数依据和估计高度，不自动回填总层数。当前逐栋结果、55项测试与正式服务待重启状态见[小吃街审核](snack-audit-2026-09-24.md)。下文验收数字为1.3.0历史记录。

## 队员怎么用

1. 登录后先搜索店铺，点击“领取并补充”；没有记录再进入“填写信息”申请新增。
2. 对象类型选择“地点 / 店铺基本信息”，点击“打开三维地图选位置”。首次加载约29 MB，网络较慢时可先文字填写。
3. 拖动旋转；右键或双指平移；滚轮或双指缩放。用“俯视”定位，按“开始选点”后轻点建筑或地面。拖动不会当作选点。缺失建筑可以点其地面位置，不必猜地址。
4. 回到表单确认本地坐标、候选建筑关联；填“具体位置 / 缺楼、轮廓或入口问题”。例如“小吃街南侧第二栋，入口朝东”。这只是格式示例，不是真实采集。
5. 建筑总层数与店铺所在楼层分别填，例如“共2层、店在1层”。总层数注明“现场确认”或“目测估计”，不知道就留空；不能把白模外观当实测。
6. 填观察时间、证据说明，可附门头或建筑照片，保存草稿或提交审核。提交失败保留页面。草稿和退回记录通过“继续填写”恢复，包括地图位置。

同楼多店分别建记录；需要整体建筑纠错时选“建筑 / 缺失建筑”。选点不会自动修改名称，也不会立即改变白模。经纬度与三维选点只能保留一种。

## 管理员核对

进入本机管理员页面，在提交卡片点“在三维地图核对位置”。检查选点是否正确、关联是否误绑、层数依据和照片是否支持结论。批准后更新正式POI位置与属性；模型几何保持原样，缺楼补建另行实施。

默认全景只取校园，不为枫蓝国际等远处地点拉远视野。模型之外仍可文字或经纬度填报；数据没有删除。

## 上线与验收状态

新增功能在独立测试服务完成白模加载、点击回填及草稿保存检查；自动测试49项通过。没有新增真实调查记录，没有重建建筑。

本次自动重启现有8790/8792进程被工具执行策略拦截，因此团队现有入口尚需本机重启才能使用新地图接口。检查并运行项目根目录 `restart_contribution.ps1`，然后刷新原团队链接；脚本沿用现有隧道，不安装服务、不更改密钥。如果8790未运行或进程不匹配，脚本会停止而不操作其他进程。

## 本次纠错总结

- 只查内置浏览器不能断言Edge不可访问；原生computer-use实际发现了Edge，但读取被网址识别策略拦截。
