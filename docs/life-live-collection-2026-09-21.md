# 1.1.1 百度实采与纠错记录

本记录续接 1.1.0 交付文档；旧文档中的“缺密钥、未执行在线采集”描述仅代表上一阶段。

## 实际结果

- 使用用户临时提供的密钥，未保存到项目、环境配置或日志。
- 矩形检索返回 9；基础城市与圆形详细检索可用。改用圆形覆盖原网格，并按原业务范围筛选。
- 采集器累计尝试 136 次（包含最初矩形失败；另有 3 次权限诊断请求）。本轮圆形运行 135 次尝试，最终收到 302 当日配额超限并立即停止。
- 172 个初始任务中，3 个因数量不足拆为子任务；当前 184 个任务节点、181 个叶任务，完成 127 个，待执行 53 个、配额失败 1 个。未完成叶任务共 54 个，不能宣称全部采集完成。
- 本轮原始响应去重发现 295 个 UID。结合既有审计共处置 332 个 UID：范围内收录 225 条，附近非餐饮 67 条，范围外 40 条。范围内百度记录比此前 13 条增加 212 条。
- 合并官方/已有清单/SQLite 后，API 共 256 条地点记录；包括校门、历史记录和待核对同店关系，不能称为 256 家独立营业店铺。
- Shop 对象 246 条，其中 20 条为模拟窗口；Item 仍为 200 条明确标注的模拟菜品。新商户缺真实菜单时不凭人均消费生成商品。
- 12 组疑似重复、44 条候选更新保留待核，不自动覆盖原有内容。既有 SQLite 表结构和 19 条记录未迁移。

## 验证与边界

27 项生活业务测试、9 项原有测试通过；涵盖圆形模式锁定、配额停止、细分、分页、商户稳定 ID、缺菜单、只读旧库、推荐及预约。前端脚本语法检查通过。

原始响应及无密钥参数在 data/life/raw；名录、来源、覆盖与缺口导出到 data/life/exports 的时间戳目录。API 的 /coverage 提供 unfinished_tasks 和配额提示。

## 纠错总结

1. 有密钥不等于所有检索方式都有权限；先做最小权限诊断，保留失败证据。
2. API 报告 total 与唯一 UID 数不足时不能算完成；细分后仍不足保留缺口。
3. 按时间而非文件名顺序选快照；新旧内容差异仅生成候选更新。
4. 新店铺录入与菜单补全分开；缺真实价格就不编造预算可行性。
5. 配额超限是外部阻塞，不重试轰炸、不修改账户或自动购买额度。

## 下一步

配额恢复后，在运行进程临时提供 BAIDU_MAP_AK，执行 `python -m backend.collector --max-requests 300`。程序沿用 circle 模式和断点；不重新抓取已完成任务。完成后重新导出。仍需补齐窗口、菜单和人工名录核验；自然语言 Agent 与正式美团/学校接口不属于本次实采。
