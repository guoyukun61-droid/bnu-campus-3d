## 2. 整理后的关系

```text
物理楼栋 building
  └─ 已知楼层 floor
       └─ 场所 poi（如新三、新四）
            ├─ 既有真实窗口 outlet → 菜单组 menu_group → 商品 item
            ├─ 待核菜单组 menu_group → 商品 item
            └─ 历史楼层供餐集合 collection（保留原Shop身份，不再当独立窗口）

区域 area ← member_of / ordered_along ← POI
参照建筑 ← relative_to ← POI
待定位同楼组 building_group ← same_building_member ← 多家店
```

稳定对象ID与可修改的显示名称分开。菜单组按固定照片证据身份登记；改菜单标题、价格、文件路径或记录顺序不会重新造组。没有稳定证据时保守按原Item单列，不能靠同名自动拼成商户。

- `ref={kind,id}`：用户正在查看的实体；不同类型不会因ID同名而混淆。
- `outlet_id`：已存在的真实窗口/店铺关联；身份未确认时为null。
- `group_id`：照片或既有店铺菜单的组织单位，不等于窗口ID。
- `map_target`：可定位到楼栋、既有点、参照区域、区域列表或未知；不伪造店门坐标。
- `data_mode`：real / simulated / inferred，沿Item→Shop→POI继承；real仅说明不是演示/推测来源，不代表现实已全部核验。
- `operational_status`与`source_active`：状态独立于来源；关闭/历史父记录不能让子菜单漏进普通查询。
- `breadcrumbs`：沿可靠包含关系生成，不把“在西侧”写成“在该建筑内”。

淮南牛肉汤仍位于四层；来喜福与学五同楼，两条疑似同店记录暂不合并；两处瑞幸的科技楼二层/新乐群三层关系保留。西侧乡村基、塔斯汀、鹏记、夜罐罐和库迪进入同楼组，但不绑定到作为参照的西北食堂轮廓。

### 已实现的只读接口

这些路由会在**下次以新代码启动的app_server进程**生效，本轮未重启旧服务。

| GET路径 | 用途 |
|---|---|
| `/api/app/v2/summary` | 快照版本、计数和问题 |
| `/api/app/v2/entities/search?q=新三&kind=poi` | 按名称/别名搜索，完整分页 |
| `/api/app/v2/entities/{kind}/{id}` | 单实体、面包屑、来源及地图目标 |
| `/api/app/v2/entities/{kind}/{id}/children` | 包含子级、区域名录及同楼组成员 |
| `/api/app/v2/menu-groups/{id}/items` | 单组菜单，不混合整层 |

分页默认24，上限60；`cursor`绑定查询、过滤和snapshot。修改搜索条件必须弃用旧cursor。保留最近3份快照；旧游标失效返回409 `SNAPSHOT_EXPIRED`，不能接上不同版本。

普通查询默认排除模拟/推测业务记录，`include_simulated=true`为显式演示查看开关，会包含这两种非真实来源；逐条保留data_mode。建筑/区域实体本身可以浏览，推测的只是其简介字段，`content_origin`和“推测：”文字持续可见。已停用记录仍保留在整理包，但不出现在普通实体列表。

旧`/api/app/place`保留平铺menu与offset以兼容尚未升级的UI，增加menu_groups、group_id、outlet_id等字段。旧建筑接口保留原5字段白名单，新版接口才提供完整来源。**所以本轮没有把旧页面的菜单视觉改成分组导航**；下一轮前端只需消费已准备好的接口。

真实推荐现在只能使用允许的菜单/现场/官方单品依据；不接受推测价格。`exclude_outlet_ids`可只换同楼某窗口，不能传楼层/菜单组ID。身份未核实的集合仍保守去重，不声称它们是3家独立商户。

## 7. 本轮纠错总结

- “数据已经录入”要分成原记录存在、归属正确、API可查、页面可发现四层；不能再只数POI。
- 先修数据粒度，后改UI。前端延后期间，明确旧扁平展示仍存在，不把新接口当作新界面已上线。
- 菜单组/楼层集合不是已确认窗口；窗口数不等于照片数。
- 来源、经营状态、位置精度是三个独立维度，不能靠单一verified布尔值代替。
- 来源标记必须穿过DTO与父级传播，不能在序列化时把inferred改成published。
- 软件验证使用虚构样例；官网正文、实地核验、真实模型调用分别报告。
- 本轮未修改账号、聊天、密钥、原始业务记录、SQLite schema、模型几何、前端样式、Git历史和公网运行进程；没有push。
